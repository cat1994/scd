# SCD experiment reproduction

This anonymous package contains the execution engine, raw tournament records,
data validation and storage code, and figure/table generators for the seven-game
SCD experiments. All commands below run from the repository root on Linux.
No external experiment directory or server account is needed.

## Contents

- `hr_edl/src/`: C++ fixed-tournament engine and a self-contained subset of its
  OpenSpiel, Abseil and Eigen dependencies. No dependency Git histories or
  prebuilt executables are included in the release archive.
- `bin/`: launch the main experiment and ablations, save validated analysis
  datasets, and plot the learning curves.
- `hr_edl_data/`: strict raw-record parser, method definitions and aggregation.
- `data/raw/main/`: 7 original main runs; `data/raw/ablation/`: 21 original
  ablation runs. Numerical tuple text is preserved; labels and file names use SCD.
- `data/derived/`: archived endpoint tables, game statistics and validation evidence.
- `data/provenance.json`: current and original raw-file hashes, method pools,
  naming migration and original timing setup.
- `figures/reference/`: the three PDFs used by the manuscript.
- `scripts/`: regenerate tables and game statistics, verify the release, and
  export a clean archive.
- `tests/`: parser, configuration and output-protection checks.

New runs and regenerated artifacts go under `outputs/`. The archived raw data
is protected against accidental overwrite by the launch and storage commands.

## Python environment and data-only reproduction

Python 3.10 or later is required. The tested analysis versions are pinned in
`requirements-reproduce.txt`; the optional package installation is not needed
when running the scripts directly from this directory.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-reproduce.txt
python scripts/verify_release.py --full
python bin/save_data.py --family main
python bin/save_data.py --family ablation
make figures PYTHON=python
make tables PYTHON=python
```

The storage step writes `outputs/data/main.npy` and `ablation.npy`. Plotting
accepts either these trusted local NumPy files or the raw directories directly.
The default `make figures` reads raw data and writes three PDFs and PNGs to
`outputs/figures`; `make tables` writes CSV, JSON and two LaTeX tables to
`outputs/tables`. The default uses portable MathText fonts; set `SCD_USE_TEX=1`
when a TeX installation with `amsmath` and `siunitx` is available to use TeX
typesetting. Numerical curves are identical under both font modes. The original
manuscript PDFs are retained under `figures/reference`.

NumPy object datasets use pickle internally: load only trusted
files generated by this package. Raw SSV files can always be used instead.

## Build and rerun experiments

The default C++ build retains the original native-CPU optimization settings.
For a portable binary, configure with `-DSCD_NATIVE_OPTIMIZATION=OFF`; numerical
trajectories can differ near degenerate or zero-regret decisions.

The C++ build requires CMake 3.16+, a C++17 compiler, Make and pthreads. Its
vendored dependencies allow an offline build; the Python dependencies must
already be installed for the launch/analysis scripts.

```sh
make build JOBS=4
make test
make smoke
```

`make smoke` performs a three-round Kuhn main tournament and all three
three-round ablations. It writes validation data to `outputs/smoke` and refuses
to overwrite existing results. Use a fresh `--data-dir` to repeat a run.

To run the complete paper configuration (1000 rounds):

```sh
make main
make ablation
```

The main command uses 4 threads per run and at most 8 concurrent jobs; ablations
use 2 threads per run and at most 6 concurrent jobs, matching the archived
configuration. Reduce `--threads-per-run` and `--max-parallel-jobs` in the
launch commands for a smaller machine. The direct launchers default to one
thread and one job. Full runs, especially larger games, can be expensive.

```sh
python bin/run_SCD_main.py --dry-run
python bin/run_SCD_ablation.py --dry-run
python bin/run_SCD_main.py --games kuhn_3p --iterations 10 --data-dir outputs/example
python bin/run_SCD_ablation.py --games kuhn_3p --scd-budgets 1 2 4 --iterations 10 --data-dir outputs/example-ablation
```

The seven benchmark definitions are in `hr_edl_data/experiment_parameters.py` and recorded in every
run's `.ssv.meta.json`. Fixed means independent, evolving opponent self-play
trajectories; focal learner updates do not change those trajectories. It does
not mean repeatedly using one final frozen opponent policy.

## Methods and metrics

| Raw method identifier | Manuscript method |
| --- | --- |
| `CFR` | SCD_0 |
| `k-SCD` | compressed SCD_k |
| `k-SCD_UNCOMPRESSED` | uncompressed SCD_<=k |
| `A-EFR_IN` | ACT_IN |
| `CSPS-EFR` | CSPS |
| `BEHAV-EFR` | BHV |

Source code, raw labels, metadata and derived tables use the same SCD
identifiers. The `scd_main` and `scd_ablation` file prefixes identify the two
experiment families. The parameter k is named `scd_budget` in code and metadata,
`--scd-budgets` (or `--k`) in the Python launchers, and `--scd_budget` in the
C++ engine. The shared launcher is `bin/run_all_scd.py`.

The main experiment has exactly a 7-by-7 pool including diagonal
matchups. Each of k=1,2,4 has its own 2-by-2 ablation pool, also including the
diagonal. Tiny Bridge and experiments from other projects are outside this
package's scope. All archived runs use uniform initialization, full-tree
expectations (`sampler=null`), epsilon=0 and CFR+ disabled.

The raw tuple stores pre-update expected payoff, learner milliseconds, the
maintained local regret numerator, an untruncated retained-local numerator,
and diagnostic milliseconds. The raw files also contain auxiliary BR rows;
these are preserved but excluded from the paper's learner pools.

- Payoffs are averaged across focal seats, cumulatively averaged over rounds,
  then averaged equally over the exact opponent pool. Poker plots multiply
  utility by 1000; Goofspiel plots use `50*(u+1)`, which is not a literal win
  probability in the three-player games.
- The plotted OSR statistic is the maximum maintained local EX/IN positive
  cumulative regret across seats and information sets, divided by the update
  count, then averaged over opponents. It is not an exact full-response oracle.
  Endpoint tables display this already averaged value in units of 10^-3;
  multiplying by 1000 for display is not a second division by iteration count.
- Runtime sums focal value evaluation and updates. It excludes opponent
  self-play, diagnostic reads, output and plotting. Runtime curves pair values
  at the same round; they do not interpolate every matchup to a common time.
  Main and ablation timing setups differ and must not be compared as identical
  wall-clock configurations.
- There is one deterministic trajectory per ordered matchup, without independent
  repeats or confidence intervals. Hardware, compiler and floating-point
  behavior can affect newly measured runtime and trajectories; see
  `VALIDATION.md` for the checks performed on this release.

## Optional game-size and utility statistics

These scripts use the Python OpenSpiel 1.4 package, independently of the
vendored C++ experiment engine. Archived results are included, so this optional
installation is unnecessary for the learning curves and endpoint tables.

```sh
python -m pip install -r requirements-stats.txt
python scripts/count_game_sizes.py --output outputs/stats/game_sizes.json
python scripts/count_memory_depth.py --input outputs/stats/game_sizes.json --output outputs/stats/memory_depths.json
python scripts/audit_game_utilities.py --input outputs/stats/game_sizes.json --output outputs/stats/game_utilities.json
```

The memory-depth script also writes `decision_counts.json`: maximum own
predecessor depth plus one current decision. The utility audit distinguishes
properties of the actual selected instance from the broader game model.

## Integrity, export and attribution

`SHA256SUMS` covers the distributable source, data, reference figures and
licenses. Verify it before analysis. Do not regenerate it merely to conceal an
unexpected discrepancy. After intentional modifications, review the changes
and update the release manifest before exporting a new release.

```sh
python scripts/export_release.py
```

This writes `outputs/scd-anonymous.zip` from the manifest only, excluding Git
history, local configuration, environments, build products and new outputs.
The archive is created exclusively and never silently overwritten.

The naming migration changes algorithm labels and file paths only: numerical
tuple text, round indices and auxiliary BR rows are preserved. The provenance
manifest records each current raw-file hash and its pre-migration
`original_sha256`; sidecars also retain `original_output_sha256`. Sidecar
source and executable fingerprints describe the original archived engine;
`SHA256SUMS` covers the current release source. Sidecars retain scientific
settings while removing machine paths,
private repository history and original run identifiers. Public third-party
copyright and license notices are intentionally preserved; they are not
attributions of authorship for this paper. See `LICENSE.txt` and
`THIRD_PARTY.md` for the inherited code and dependency notices.
